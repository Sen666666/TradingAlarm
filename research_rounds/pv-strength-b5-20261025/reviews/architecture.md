# B5 独立架构审查

审查日期：2026-10-25。角色：独立阅读冻结 E0/B4 的审查者；未参与 B5 模型实现，不运行账户。审查范围仅为量价证据与 E0 参与规则的分层、行为兼容和因果边界。

## 设计阶段裁决

设计方向可行。B5 必须作为新版本保留 E0 原事件事实与冻结 B4 的并列描述，而不能将 B4 的 S/μ 当成原 E0 事件的近似替代。旧 E0/B4 源码和既有研究证据保持只读。关闭增强时可验证的目标是同一适配合同下的逐日 E0 状态与记忆台账精确相等；这不等于证明经济有效，也不等于当前 B4 原生输出原本就能复现 E0。

冻结 `numeric.event_frame_numeric` 同时实现事件检测及一套内部支持/参与规则。新的事实核可提取其事件计算，但必须移除 `active/floor/target/entered/exited` 及其分支；原事件的方向/极点演化并不依赖这些字段。新的 `e0_policy` 应自维护 E0 `active/floor/pending`，只消费显式市场证据，不能调用冻结 `participation_frame` 或读取导入的 E0 状态。

## 必须保持的双时钟

| 行为 | 正确时钟与缺失语义 | 容易发生的错误 |
|---|---|---|
| 原摆动事件 | 当前段正且有限 C/V 的子集；第 65 个该类观察开始准备 | 用价格有效数提前预热，或先补零量再计算 |
| B4 原生描述 | 显式 `valid_strength_observation` 子集；逐段调用冻结实现 | 缺量行仍更新 EW/候选，或跨段搬运状态 |
| E0 参与与价格响应 | `valid_price_observation` 的有序子序列，包括量未知但 OHLC 有效的行 | 全部按 C/V clock 压缩，漏掉缺量日退出或收复 |
| E0 量比 | 有效价格序列上 V 无效处保留 NaN，`shift().rolling(21,min_periods=21).median()` | 先丢弃缺量再滚动，使之后 21 个观察误变成可用量比 |
| 记忆等待计数 | 有效价格观察数；缺量有效价格行会计数 | 使用事件观察数或自然日差 |
| 退出后的前收盘 | 上一有效价格观察，即使该观察量无效 | 使用上一事件观察的收盘 |

分段重启和无效价格行输出未知属于 B5 显式适配合同。冻结原始 `participation_frame` 本身不会自动识别来源段，也不能直接接收任意无效价格。因此应将“100%”表述为：逐段抽取相同有效价格子序列，送冻结事件函数及参与函数作为只读 oracle，再按相同索引对齐。不能把新适配行为追溯称为旧 raw 入口已有的保证。Ledger 的 id 在段内重启，需要 `segment_id` 区分，不能默默宣称全局唯一。

## 必须覆盖的顺序反例

1. 收盘等于旧支持即退出；同日向上事件不能重入，但当日高量下跌仍可能创建新记忆。
2. 收盘等于 pending.lower 或 pending.reclaim 均不触发价格响应；严格小于 lower 才否决，严格大于 reclaim 才收复。
3. 旧记忆在当天被否决后，若仍空闲且当天满足高量下跌，可立即创建下一项记忆；ended_id 与 pending_id 不同。
4. 旧记忆收复与原向上事件同日发生时，原事件入场优先，支持用原极点，记忆结局为 `base_confirmed`。
5. 旧记忆否决与原向上事件同日发生时，否决结局保留；原事件仍可单独入场。
6. 已有效时向上事件只抬高保护点，比较相等保留原值；旧支持的退出检查必须早于当天抬高。
7. 有效价格但缺量的行可退出或收复旧记忆；不得新建依赖高量条件的记忆。随后量比的未知期须与冻结 rolling 运算一致。
8. 来源段切换必须清空所有事件、B4 和政策状态；未知价格行不产生市场事件或参与动作，也不推进任何有效观察时钟。
9. 既有同 C/V、不同 L 的双路径反例：B4 描述保持相同，事实层保留 L 差别，政策支持/退出分别恢复 98/94 与收盘 96 时的分歧。

## 实现审计验收标准

- 静态检查新的事实层不含政策状态，不导入或调用冻结 participation；E0 政策不调用旧事件/参与函数、不读取 `strength_*`。
- 动态删除、替换全部 `strength_*` 后，E0 逐日状态和完整 ledger 不变。
- 输入附带任意伪造 `e0_*` / target / entry / floor / pending 列时，事实输出不变；调用政策不得原地改写事实数据或 journal。
- 冻结原事件的市场字段与新提取结果逐列精确比较；B4 101 原生列及 journal 在仅增加命名空间后精确保留。
- 真实已有输入、必要合成边界、分段缺量及物理截断前缀分别验证，不只比较 entry/exit 日期或最终收益。
- `enhancements=True` 明确拒绝；本轮没有新强度公式、新参与增强、阈值搜索或账户准入。

## 最终实现审计

审查结论：**已通过本审查者负责的分层边界验收，未发现未解决的架构阻断项。** 本裁决对应下列收据登记的源码字节，不替代本轮全历史、合成矩阵和前缀兼容验收，也不作经济有效性判断。

- [架构边界收据](audit/boundaries-v1/receipt.json)：27/27 通过；[独立脚本](audit/audit_boundaries.py)。
- [输入与稳定 schema 收据](audit/input-edges-v1/receipt.json)：8/8 通过；[独立脚本](audit/audit_input_edges.py)。
- 两组共 35 项，账户 0，未编辑生产模型，未改旧 E0/B4 文件；所有运行前后受审源码哈希一致。
- 正式冻结后额外核对两个收据的所有源码仍与磁盘相同，四个核心源也与 `freeze.json` 逐项相同，见[最终源码身份补审](audit/final-source-identity.json)。这 35 项直接覆盖含 segment/schema 修复的最终版本，不是把旧 hash 的审计挪用于新版。

实际结构为 `evidence.py` 提取旧事件的纯检测分支及无账户候选事实，`policy.py` 自行维护 active/floor/pending，`arithmetic.py` 保留旧比较和局部对数算法，`api.py` 仅串联两层。冻结 B4 在校验 SHA-256 后作为纯描述依赖加载，所有 101 个原生描述列加 `strength_` 命名空间。其内部候选状态属于量价检测器，不是 E0 的参与记忆。

独立检查确认 `compare/log_ratio/higher` 三个函数除 docstring 外 AST 与旧源码相同；事实模块无 active/floor/pending/target/entered/exited 代码状态，政策模块无 `strength_*` 字段常量，生产导入无旧 numeric/participation。实际生产执行栈也未调用旧 E0 文件；旧参与函数只在审计脚本明确的 oracle 区段运行。

动态隔离的关键结果为：向原始输入添加伪造 e0/target/floor/pending/account_cash/pnl 列不会改变事实、日志或 attrs；删除全部 strength 列并清空 attrs、或把它们毒化为不可用字符串，政策状态与 ledger 仍逐项精确相同；政策调用及拒绝未实现增强均不改写事实。改变合法 C/V 行的强度有效 mask 确实改变 B4 输出，却不改变原事件、E0 政策或原事件日志。这一测试直接覆盖三时序分离，而不是只证明两个新入口恰巧输出相同。

另一真实事件核合成反例在收复日设成交量未知：该日仍以价格 clock 收复并入场，次日收盘破支持退出；原事件列、完整政策列和完整 ledger 与冻结 oracle 精确相等。另构造原事件已入场后的高量下跌：事实层照常创建候选事实及收据，政策因已 active 而不创建 pending。由此确认候选事实不随政策的参与状态消失。

审查中提出两项边界完善，核心实现已在冻结前修复并通过新增测试：不同 segment 原身份字符串化后碰撞（例如整数 1 与字符串 "1"）现会拒绝；独立 policy 入口同步拒绝同自然日多行、空白 segment 与缺失二值候选事实。另测试 agent 发现未来无效价格行会改变过去列 dtype，最终 state 全部整数列固定为 nullable `Int64`，追加未知行后过去完整 state 及 schema 保持一致。与旧 oracle 比较时只把其整数 schema 显式转换为该公共 schema；没有浮点舍入，也没有用 allclose 容差掩盖 floor 差异。Ledger dtype 保持旧版。

严格兼容的解释来自状态依赖：旧 numeric 的 direction/ext 只依赖量价及先前 direction/ext；移除它内部未被 E0 使用的 active/floor 分支不会反馈事件演化。新政策保持相同初态、证据和逐日处理顺序，因而可以逐步复现旧政策。上述逐运算检查与反例测试支持该拆分，但有限测试不构成对所有浮点极端值或任意新数据源的无限保证。B5 没有新增强度公式或增强参与规则，`enhancements=True` 明确拒绝；本次只是保留旧证据、明确分层并验证关闭增强时的兼容性。

另只读浏览了正式真实验证器：分段 oracle、ledger 当时投影、完整字段与物理前缀的比较逻辑未见明显盲区。该 runner 自身只记录 freeze 身份、不独立执行其全部登记校验，保存 B4 日志也有存在性分支；本轮由主 agent 和真实验证 agent 在独立收据中另行核验全部 77 个冻结身份及 7 份保存日志存在。此为本轮执行约束，未来单独调用 runner 时也须执行这些外层核验，不能把 freeze 文件“存在”当成源码身份相同。
