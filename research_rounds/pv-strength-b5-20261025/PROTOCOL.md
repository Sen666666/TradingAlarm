# B5固定实现与兼容核验协议

本协议在正式输出前写定。目的为可验证的向后兼容，不评价收益、不以复现E0证明强度有交易增益。

## 1. 三个明确边界

1. `build_evidence`：仅以量价及显式数据有效性/来源段计算事实；提取E0的原事件核、量比与放量下跌候选事实；并行给出冻结B4的强度、结构和冲击。不得维护E0 active、floor、pending，不读既有E0结果。
2. `e0_policy`：只消费事实表，自行维护E0的active、保护点、未决记忆与同日优先级。关闭增强时不读取strength列。可以离线接收已经序列化的事实表，不重新读取行情文件或重算市场事件。
3. 执行与账户：不在本轮范围，信号资格不等于实际成交。

旧E0原函数与B4原始结果只作为只读对照。B4纯描述核可作为固定依赖复用；旧E0参与函数不得在B5生产实现中调用。提取E0事件核时保留数值操作和比较规则，不借机优化或改变公式。

## 2. 输入与三个计算时序

日线OHLCV、segment_id、valid_price_observation、valid_strength_observation显式输入；日期有序、唯一、无时区、无空值，同自然日多行拒绝。段编号不可复用；字符串化后会碰撞的不同段身份（如整数1和字符串"1"）拒绝，不能在日志中悄悄合并。缺失/非上市期不补造观测。

- 价格时序：每段有效OHLC行，允许成交量缺失、零或非有限。E0的previous_close、等待时长、保护点检验及旧记忆响应沿此时序推进。
- 旧事件时序：价格时序中C/V都正且有限的子序列；保持原RMS63、滞后量中位数21、√5尺度和整摆动均量公式，t64起准备。结果回对价格时序，缺量行event为0但不强迫E0退出或失去准备状态。
- 强度时序：显式strength有效行，必须属于price有效且C/V正有限；冻结B4按它自己的原合同运行，保留第65有效收盘公开与所有原参数。

旧参与量比另在完整价格时序以V.where(正有限).shift().rolling(21,min_periods=21).median()计算，不能dropna后滚动。它与旧事件核的量时序可能不同，必须分开命名。

每段重置；price无效行不处理政策，映射输出未知。分段/未知输出是显式适配合同，100%指在同一适配后对比原函数，不宣称旧raw入口已经有此语义。没有任何正有限V的段，B5保持事件未准备；原事件函数会拒绝该输入，因此作为扩展输入边界测试单列，不虚称原函数恒等。

## 3. 证据内容与政策内容

证据含原OHLCV与两类有效性、每段观察序号；原摆动event、确认值、发展极值和已确认极点及日期；准备状态、前收盘、量比基准、下跌与高量事实；无条件的放量下跌候选下界和收复价。候选事实可以发生在E0有效期间，不受active门控。

强度列统一加 `strength_` 前缀，含冻结B4的全部101列。journal分别保留纯旧事件收据与B4原样日志。没有E0 target/floor等对照列混入事实接口。

E0政策读取当前事实、自身active/floor/pending；按原先次序处理：旧保护点触及退出 → 旧记忆价格响应 → 原向上事件优先入场/抬支持 → 消费/否决/收复旧记忆 → 空闲且无记忆时接收当日新候选。退出当天不得重入但可以新建等待记忆。向下事件本身不卖出，保护点只随原向上事件提高。未成交订单、实际持仓、入场价、费用不属于本政策。

`enhancements=False`为唯一已实现政策。传True明确拒绝，不能制造一个名字叫增强但实际未实现的模式。强度公式不变；未来增强政策须另外冻结。

## 4. 事前固定验证范围

1. 同批7个完整来源：AU0、518880、512480、001309.SZ、688981.SH、600036.SH、600519.SH。来源为原B1冻结inputs；沿用该批比较的有效观察/段标记，与B4原全列及E0已有5列对照，不只抽失败日期。
2. 原E0 source-precision-v1内全部8条非港股来源：USHJ518880、USHJ512480、USHJ510300、600919.SH、600059.SH、600917.SH、URFI881129、UZZI000994。使用原eligible_prices与保存排除日，进一步覆盖旧E0价格时序和缺量处理。与上一组的同资产不同版本不当作独立样本。
3. 独立测试agent预写有限合成矩阵与policy边界；原事件端到端与注入事件的政策单测明确分列。包含已知low98/94反例、预热、平价、急跌/V、低量与放量、缺量退出/收复、支持容差、长等待、同日冲突、来源重置与无效行。
4. 每条真实来源固定物理截断点：第65行、约1/3、约2/3、倒数第1行，重复点去重。核对过去全部证据、政策字段和日志，不把截断运行当新账户。
5. 关闭增强时删去所有strength列、扰动所有strength列均不能改变政策；事实表Parquet保存/重载后政策保持一致。缺失必需事实应拒绝；不得默默回读旧E0补齐。

## 5. 严格相等与可证伪条件

原事件共同字段、E0全部政策字段、保护点和未决记忆记录使用exact比较，缺失值按相同位置相等；不以allclose掩盖边界变化。B5政策整数状态列固定为nullable Int64，确保未来是否出现无效行不会改变过去列类型；对原oracle整数列先作同一明确类型转换，再exact比较值与缺失位置，浮点数不做舍入。额外segment_id用于定位，不计为旧公式差异。Ledger末尾未解决项比较须按前缀的当时状态投影，不使用未来解决日期。

B4完整强度列、日志与当前同输入调用必须精确相等；原7来源还与已存B4结果相等。旧7个E0保存列的ready/target/entered/exited/floor要单独核对，不能只让两个新实现相互一致。

审查生产依赖与字段边界，确认E0原policy只在验证代码使用。再证明事实可独立序列化、策略可不见强度、两者无法读账户。保留失败收据，技术修复重新冻版后再跑必要验证，不按结果更换标的或阈值。

本轮通过只证明该版本在登记样本、合成与边界下实现精确兼容；逐运算拆分与状态归纳提供解释，但有限测试不构成对任意数据源、未来市场或所有浮点输入的无限保证。旧E0/B4源与全部旧结果哈希不变。不作收益、胜率、回撤改善判断。
