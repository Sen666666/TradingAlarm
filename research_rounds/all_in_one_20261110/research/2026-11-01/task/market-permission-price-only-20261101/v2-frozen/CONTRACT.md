## 1. 身份与解释边界

- 一个候选：独立的四状态许可 WAIT / ACTIVE / REPAIR / ENDED，另有显式 `pending_price_failure` 待判标志。全局与每个行业分别持有自己的 State；无账户参数，无跨层级 AND／OR 总闸。
- 价格前沿为 PRICE-only；广度仍是原金额调制方向动量。不给全局复合价格虚构成交额，不冒充 CP1 原收据、实际止损、损失上限或本金保证。
- 许可只回答本域下一可消费开盘是否允许新增风险。它不产生订单、资金、预算券、卖出义务；旧仓退出沿原规则。70% 总容量及 20% 行业上限均未解决，不能称已具备近满仓参与能力。
- 旧 407 科技／11 行业与新 1709 股票／90 行业严格分源。当前存续、分类、市值快照回看有选择偏差，不是 PIT 或样本外。

## 2. 输入与原广度／BREAK

`Observation(at, source, close, breadth)`；`Source(universe, price, breadth, revision)` 记录股池、价格构造、广度口径及源片段版本。`scope` 固定标识一个全局或行业流。

`at` 必须为同一格式、可按字典序比较的已完成收盘时间／观察序号，严格递增；重复、倒序拒绝。只喂该域计划观察钟：休市不造空行，计划钟上的缺失保留空值。历史修订不能原位改过去；应作为明确新版本重新审查。

原股票方向量：

`r = diff(log(causal_close))`

`x = r × min(1, sqrt(amount / median(previous 21 amount)))`

`m = EWMA(span=21, adjust=False)(x)`

原源片段首 64 观察抑制；行业内有效 m 至少 5 股，广度为其中 `m>0` 的比例。全局等权平均有效行业广度，至少 8 行业。零 m 是已知非正，未知 m 不进入分母；不是当日上涨家数、净流入或概率。

全局原价格为行业等权股票平均 log 收益的累计复合；原 `refresh.py` 对未知 aggregate return 有 `fillna(0)`，所以已存 price 数值有限不自动证明当次价格真实可观察。历史接线需独立恢复有效观察来源，不照搬填零为已知。

本纯函数不重算广度；上游仅可在原覆盖门通过时提供 `[0,1]` 值。行业使用自己的原 m 分母（至少 5 股），不套全局 8 行业门。行业价格为绑定的真实行业源，与全局合成价格不同。

启动谓词使用原 BREAK 形式：`C > max(previous 63 price observations)` 且 `C > previous_close` 且 `breadth > 0.6`。63 个此前价格槽均须已知；缺价不偷偷压缩滚动窗口。行业独立将同一谓词应用于自己的价格／广度，不消费全局 BREAK。原 CSV 的 `fast_on` 不进入新候选。

## 3. 尺度与前沿（当日收益不入当日尺度）

`s_t = max(1.4826 × median(abs(previous 63 valid log returns)), log(1.001))`

这里是绝对 log 收益中位数，不先减去收益中位数。有效收益仅由同源、相邻两个计划观察的已知正价格形成；不跨缺价补一条多日收益。至少 63 条此前有效收益才有尺度，初始化须同时满足原 BREAK；无额外五日等待。

每个价格片段冻结尺度 `s_segment`、锚 A、已见最高前沿 H 和信用 Q。初始化 A=H=C、Q=0。每次仅新增 `max(0, log(C/H_old))`，令 H=max(H,C)；重复高点、横盘或来回震荡不能再生信用。Q 达到 `sqrt(5)×s_segment` 则发生一次推进事件。当次候选线 `C×exp(-sqrt(21)×s_segment)`；事件多大也只发一次，不把单跳拆成五份独立证据。新片段 A=H=C、Q=0，并冻结当次开盘前已知的 `s_t`。

无金额前沿调制时，Q 与 `log(H/A)` 是同一价格位移的不同记账；不把信用与位移称作两份独立证据。常数 sqrt(5)、sqrt(21)、63、1.4826、log(1.001)、0.6 不扫描或为案例调整。

## 4. 转移顺序与时钟

输入 State.line 是**本观察已经生效的旧线**。先处理旧线失败，后处理价格推进。返回 State.line 才是下一观察使用的线；Decision 同时记录 line_used 与 next_line。输出来自本次收盘，只供下一可消费开盘，不追溯解释当日成交。

根据本次裁决“触及旧线”，统一采用 `C <= old_line` 为价格失败；相等也失败，广度已知与未知不改变触线含义。v1 的严格 `<` 比较已留在父目录。价格推进用 `>=`，广度用严格 `>0.6`；没有根据历史结果调整。

| 输入状态 | 当次已知条件 | 收盘后状态及动作 |
|---|---|---|
| WAIT / ENDED | 原 BREAK 且尺度就绪 | ACTIVE；收盘建立锚、前沿、初始线 `C×exp(-sqrt(21)×s_t)`，Q=0；下一开盘可许可 |
| WAIT / ENDED | 其余 | 保持；反弹、修复信用或旧账户恢复都不能启动 |
| ACTIVE | 已知价格触及／穿过旧线，广度未知 | 记录不可改写失败收据，撤销许可；进入无锚的 pending 等待，处理规则见第5节；不猜广度正负 |
| ACTIVE | 已知价格击穿旧线，已知广度>0.6 | REPAIR；立即关闭下一开盘许可，累计失败；以失败收盘建立修复锚与冻结尺度，Q=0；此观察禁止恢复／重新 BREAK |
| ACTIVE | 已知价格击穿旧线，已知广度<=0.6 | ENDED；累计失败、销毁已失效价格上下文；本观察不能重新启动 |
| ACTIVE | 未观测到破线且价格已知 | 按前沿积信用；推进时 next_line=max(old_line,candidate)，更新价格片段；广度暂低不销毁上下文 |
| REPAIR | 已知广度<=0.6（即使价格缺失） | ENDED；之后须全新原 BREAK |
| REPAIR | 价格新低 | 以新低重建锚与前沿，Q=0，修复尺度不变；不恢复 |
| REPAIR | 新前沿信用足够，且已知广度>0.6 | ACTIVE；新线下一观察生效，建立新价格片段；可以低于旧 63 高点 |
| REPAIR | 其余 | 保持；无新增许可 |

只要处理完成，`permit_next_open = ACTIVE and no_pending_failure and current_known_price and current_known_breadth>0.6`。此许可不是跨天永久凭据。价格失败后旧线立即退役，仅在不可改写日志中保留；REPAIR 尚无生效线，修复成功才给下一观察的新线。

“只上移”作用于同一 ACTIVE 上下文内的线。旧线被失败事实否定后，修复成功建立全新上下文，不强制 `max(disproved_old_line,new_line)`，否则会把合法的低于旧高恢复反复判失败。历史失败累计与最后失败时间不会因此归零。

两次失败本身不添加未授权的“两击永久封禁”门：已 ENDED 的双重失败案例不能仅反弹重启；仍处 REPAIR 则只有规定的新前沿和正广度能恢复。

## 5. 缺失与换源的唯一处理（含已裁决待判失败）

- 非有限、非正价格（含 bool）为未知；非有限或不在 `[0,1]` 的广度（含 bool）为未知；不钳位成好数据。
- 未知价格：本次许可 False，不造收益／前沿信用、不猜破线；保留既有价格上下文和已观察失败。下一已知价仍先与旧生效线比较；它只能贡献与已观察前沿相比的新增端点位移，不假设缺口中连续上涨。它不与缺口前价格拼接一条“相邻收益”。
- 未知广度、ACTIVE 价格未触线：许可 False；价格若已知仍可记录纯价格推进。ACTIVE 上下文保留。
- **已经有已知正广度锚的普通 REPAIR** 中，未知广度不终止上下文：已知新低仍重建锚／前沿、信用清零且尺度不变；已知新高仍可累计价格信用，但不给许可。之后广度已知>0.6 且信用足够时才可恢复，即使该恢复观察没有再创新高。未知价格不推进或重建锚。普通 REPAIR 与尚未建立修复锚的 pending 等待明确不同；未知广度不等于<=0.6，也不等于>0.6。
- REPAIR 中已知广度<=0.6 优先结束，即使价格未知；未知数据不能取消这个已观察失败。
- `Source` 任一语义身份变化：旧上下文 ENDED，清空旧价格窗口、尺度收益及信用，撤销 pending 标志，当次无许可，以新源重新暖机并等待新 BREAK。保留**完整不可改写失败日志**、失败计数／时间、启动和修复计数，增加 source_changes。普通文件追加不应每天更换语义身份；真实源片段／股池／方法切换必须更换。换源优先于旧 pending 分类，即使新观察完整而强，也不能用旧失败转为新源 REPAIR。

**已裁决：ACTIVE 已知价格触及旧线，但当次广度未知。**

1. 追加 frozen `PriceFailure`：序号、失败时间、当时 source、已知失败价、旧线、当时广度 None、当时因果尺度。失败计数只加一次、最后失败时间固定在实际触线观察；后续观察不得改写收据。
2. `pending_price_failure` 指向该收据；旧线、锚、前沿、片段尺度清空，修复信用为0，许可 False。不假设失败时广度正，也不将未知当作<=0.6。
3. 等待期间不形成任何修复锚／前沿／信用；期间已知低点不能被未来借用。底层此前价格窗口及相邻已知收益历史仍按同一观察钟前向记录，只用于因果暖机／尺度，不构成修复信用。
4. 第一条**后续**价格、广度、所需此前63有效收益尺度均已知的观察，只做前向分类。若 breadth>0.6，在这条观察的**当前价格与当前因果尺度**建立 REPAIR 新锚／前沿；Q=0。若 breadth<=0.6，ENDED。两种分类都撤销 pending 标志并保留原失败日志。
5. 分类观察不能恢复 ACTIVE、不能另用当次原 BREAK 启动、不能产生推进信用或新线。正分类之后还须后续新前沿推进才可恢复，初始条件与普通 REPAIR 一致。
6. 只有广度已知<=0.6、但价格或尺度仍未知时，pending 继续等待，不提前结束。这不同于已有修复锚的普通 REPAIR（已知弱广度即可结束）。缺失一直不恢复则 pending 无限等待、许可一直 False；不添加超时门。
7. 为保留四个已分类状态，pending 在 `State.mode` 中储存为**无锚 REPAIR**，但其标志拥有最高分支优先级，完全跳过普通 REPAIR 逻辑。`Decision.effective_status` 明示 `PENDING_PRICE_FAILURE`，并附失败收据。它不是已经确认的正广度修复，也没有隐藏第五个许可策略。消费者不得只读取 mode 来推断许可，唯一风险开关是 permit_next_open。

其他边界均已明示：输入时间／源身份缺失或倒序直接拒绝、不产生许可；调用方须修正输入身份而不能跳行沿用旧许可。合法 ACTIVE 来自已就绪尺度，后续保留63有效收益，所以正常同源路径不会再次缺尺度；pending 的不足尺度防护仍有独立工程用例。不支持通过手工损坏普通 ACTIVE／REPAIR checkpoint 来重定义数据语义。

## 6. 接口、持久化与隔离

`step(State, Observation) -> (new State, Decision)`；不可变 dataclass，无文件、网络、账户、订单或项目模块依赖。`run` 是对 step 的纯折叠；没有历史加载器。单独 `synthetic_runner.py` 只接受 universe 以 synthetic- 开头的测试输入及 checkpoint，不提供历史执行命令。

`dumps/loads` 对本原型合法 State 做版本化 JSON 往返；拒绝不匹配版本。checkpoint 包括 prior_closes、prior_abs_returns、前一观察价格、锚／前沿／信用／冻结尺度／旧线、状态、完整 failure_log 和 pending_price_failure。loads 复原嵌套 frozen 收据并核对计数、pending 所指日志和无锚零信用约束。恢复不允许重新暖机、重用已消费信用或换成账户状态。仅加载本程序有效 checkpoint；它不是不可信外部数据的完整校验器。

所有写入限本新目录。历史输入审计器不导入 signal_core，只读现有 CSV、JSON、Parquet 的字段／日期／清单和哈希；未重新计算历史 m、s、前沿、许可或任何账户结果。
