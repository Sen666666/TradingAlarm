# V3：B 是否已是 A 的子集

**按当前描述，是。** 这是同一信息定义的逻辑关系，不是绩效结论；未运行任何候选模型或账户。

前提必须保持一致：同 source 的原 numeric E0 正负事件交替；每次负事件都清除旧 B 基础，把其刚确认的高 H 冻为当前 A 恢复参考；新 START 不丢这条参考；A 与 B 都是本次 CLOSE 后的有效权限状态，而不是把一次 confirm_event 脉冲拿来和持续状态比较。

设 B 当前有效：最新相邻三点是 L1—H12—L2，L2>L1，且当前 C>H12。H12 是 L2 之前最近一次负事件发布的高。L2 之后若又有负事件，旧 B 已被撤销；因此 B 仍有效时，本周期最近负事件的恢复 H 恰为 H12。于是

`B_active => C>H12 = H_recovery => A_active`。

若 A 还需要负事件之后一次合法 +event 才能恢复，B 也已经有 L2 的 +event，蕴含仍成立。三值逻辑不改变真值蕴含：B=true 已要求价格和 H12 已知；同源同价域时 A 不应反而 UNKNOWN。A=true/B=false 可以发生，例如强反弹没有更高低点；A=false/B=true 则应查参考继承、price domain、额外 armed 门或状态/脉冲混用。

原 `numeric.py:109–122` 在反转确认时 `event=-direction`，随后 `direction=event`，所以同段非零事件交替；−event 当日是从高回落达到阈值才确认，C 必低于新 H。本日先撤权、再拿这份 H 比当前 C，不会同日凭同一个低门又恢复。

冻结前仍需明确：

- 负事件仅撤成熟新增，P 和持有责任不能清空；恢复 cycle 与持有 generation 应分开记录。
- P 未破且旧持有仍在时，C>新 H 是否允许先于下一个 +event 恢复；不能在实现中默加等待。此选择不改变上述 B=>A。
- 每个负事件更新的是最新高，即使它比上次高低，也应按本版描述照实记录；不能暗用 V2 的只抬不降 KA 取代 V3 当前恢复 H。P 的不回撤与恢复 H 的替换是两回事。
- 同日旧 P 已破后又有新 +event，旧 exit 必须封存；新 START 不得清掉旧未成交责任，也不能将恢复 H 偷换为其它较低峰。

若冻结稿改变任一前提，须按新定义重新判断；不能先以“两个独立分支”命名掩盖当前的包含关系。B 可继续作为 HL 结构标签展示，但不能据此声称增加一条独立许可通路。
