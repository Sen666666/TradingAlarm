# 保存交易全量归因

2026-10-20。仅以旧保存交易、决策和信号做算术归因，没有运行或导入账户引擎，没有重算交易、选择新参数或修改基座。全部历史均已看过。本分析解释累计代价，不把亏损交易的后验特征直接变成入场过滤器。

## 主要发现

累计损耗主要发生在**尚未取得明显有利位移的尝试**。大幅盈利后最终翻亏的普通交易所占金额很小。也有大量重复失败，但重复尝试与后来大赢家同时存在，不能由此推出延迟重入就会改善整个系统。

收盘MFE不足5%的失败分别贡献全部普通亏损金额的79.36%与84.72%。这不是说没有赢家利润回吐：全部周期连续保留峰值、终值与回吐，许多盈利交易也有可观回吐；但从“最后造成普通净损耗的亏损来源”看，最值得解释的是未完成推进的失败，而非先设计更紧的盈利退出。

**MFE口径限制很实质**：旧保存字段以执行入场日的复权信号**收盘价**为基准，包含退出日收盘价（实际常在开盘已经卖出），忽略入场当日开盘至收盘变动、全部盘中高低点、费用、汇率、分红和多次成交影响。它不能称为真实可实现最大收益。脚本逐笔复算并核对了全部MFE/MAE与sessions，另增加了去掉退出日收盘的诊断；普通亏损分组ETF8笔、HK1笔改变。此附加版本仍不是真实盘中MFE。完整表保留两套字段，未替换原证据。

## 首次风险与floor更新

按“首笔买入信号至最终卖出信号”读取保存的因果floor：

| 普通亏损 | ETF笔数 / 亏损百分点 | HK笔数 / 亏损百分点 |
|---|---:|---:|
| 买入后floor没有提高 | 208 / −52.8769 | 81 / −74.9441 |
| 买入后floor曾提高 | 81 / −14.6655 | 35 / −27.1488 |
| 同一成交周期内进入多个结构 | 4 / −1.8568 | 0 |

这支持“很多失败发生在尚未完成更高保护点的阶段”，不能解释成“只等提高floor再买就好”。提高floor本身需要后来的价格路径，不能用它回填入场资格；全部尾部周期都有后续floor提高，保留整个过程才是实际问题。

全量索引同时保留**状态开始时间、继承状态、买入前已提高floor、买入后提高floor、同一成交周期内新增状态**，不把2022账户初始建仓当成当日新趋势启动。

与机械审查的交叉核对：其“完整终末结构首次floor失败”与本表“买入后未再提高”不是同义。ETF低MFE失败190与188笔的差异来自：

- `id=2/5/6`：沪深300、军工、白酒在2021年已提高过floor，2022首次买入后没有再提高。买后标签计入，完整首次结构标签不计。
- `id=156 HK02820`：成交周期跨两个结构。早一结构抬过floor，终末结构未抬，两种定义方向相反。

为避免混合，排除跨结构执行周期后，完整结构首次floor失败为ETF187/231笔，贡献−45.8341/−54.8430个百分点，占低MFE亏损83.57%；HK72/94笔、−67.1406/−86.4953，占77.62%。两套标签都保留，不能挑一个数作为唯一“真正原因”。

首笔买入信号的`(close-exp(floor_log))/close`距离连续分布已输出。未抬floor亏损的距离中位为ETF3.95%、HK5.45%，与最终净回报的秩相关分别−0.82、−0.67。这符合结构失效需承受初始距离和执行缺口的机械关系。**普通赢家、尾部的初始距离范围重叠，不能由此声称初始距离阈值或更紧止损有益**。单次风险、连续失败以及相关持仓叠加需要后期固定经济政策评价，不能伪装成已证明的算法改进。

## 信号、成交与资金

展开全部2,389条日决策至28,823个资产日，并逐笔把1,417条订单唯一归入601周期；买入资金、订单费用与非订单费用单列。HK7没有出现正分数但日末仍完全无持仓的资产日；ETF17有31个，全部在该标的保存信号序列没有当日观测的日期，集中在两市休市不同步的日期。

这不支持把本轮主损耗归咎于“信号已经出现但资金完全挡住建仓”。保存决策不含拒绝原因；没有原始可成交状态复核，不能把每个缺口正式认定为假期，更不能量化为错过的可成交收益。部分成交、买入预算、初始等额配置和尾部实际资金大小仍由已保存交易描述，不能仅凭信号开关声称整个账户吃满涨幅。

## 判断与失败记录

1. 全量证据更支持“许多未展开的尝试承担初始结构距离，且连续失败累积”，不是“多数普通损耗来自15%以上利润全部回吐”。
2. “局部1日低点提高floor可能切碎趋势”在个别图上有机制依据，但当前主损耗归因不足以支持把唯一修改预算花在这一点上。归因没有证明放宽floor会减少累计代价，也可能把原本较小亏损放大。
3. 没有证据支持为了降低失败数直接延后重入；同样的通道也是现存大赢家的入口。
4. 建议保留算法本版，冻结并明确未晋升。其初始风险、重复尝试预算与相关资金暴露是后期应先冻结政策再评价的经济问题；当前分析未证明哪个单一算法改动能解决。
5. 分析代码曾在风险字段把保存的log-floor误当价格，检查出现不合理的80%距离后立即纠正为`exp(floor_log)`；最终文件已全部重新生成。没有修改旧交易或算法，前述最终风险数字均为纠正后结果。一次环境缺少scipy的失败用“排名后Pearson”计算Spearman解决，没有安装依赖。失败记录保留于本段，避免把诊断代码也当作无需审查。
6. 最终生成后增加了`--output`和已完成输出拒绝覆盖保护，没有改变归因计算，也没有再次执行计算。`summary.json`同时保留执行时与冻结后代码哈希。后续复现必须指定新的输出目录。
