# S1：板块—个股准入纯函数技术适配

本交付仅验证准入语义，经济账户0次，趋势算法修改0次；不构成历史数据认证、真实成交认证或全市场研究通过。正式仓库和共有入口未修改。实现范围先保存于 `implementation-scope.json`，再编写代码；冻结来源包含正式设计v2、设计协议、旧执行器和RS代码的哈希。

## 输入与输出

`decide(...)` 接收不可变记录并返回 `Decision`，不修改入参、不读取文件、不联网、不计算收益。

| 输入 | 必要语义 |
|---|---|
| Clock | 明确时区的共同决策时点、严格在其后的最早可执行时点、当前排名观察日 |
| Fact | 数值/布尔/ID、首次可知时间、有效区间、来源ID；快照额外标记观察时间及snapshot身份 |
| Security | 稳定证券ID，时点发行人/行业边，共同资料范围、买入资格、公司总市值、冻结个股状态和独立RS |
| Sector | 跨市场不合并的稳定行业ID，冻结行业状态和独立RS |
| Memory | 状态快照as_of、上次已知资格、是否尚在等待、候选创建时间/原因，以及已消费的退出事件/完成时间和待恢复重入标记 |
| Occupancy | 调用方已确认的持仓、待买或锁存退出；按本次有效行业/公司身份更新，带可知时点 |
| ExitCompletion | 调用方确认的本体退出完成事件，唯一event_id及完成时点；可重复投递但不得未来投递 |

输入的历史资格必须来自另行验收的时点连接。该模块不从当前快照推断历史，不构造历史发行人或行业证据。`Fact` 的日期防护不能证明调用方填写的 `known_at` 真实；证据认证仍属于数据桥接。

输出分别为新槽位推荐 `selected`、继续等待 `waiting`、继续/暂停/取消的已有买单、个股结构退出请求、资格原因、整批排名降级原因和容量拒绝原因。`selected` 不是委托，也不意味着资金、手数或成交容量已经通过。

## 固定语义

- T0只不要求行业趋势向上；它仍受与T1/S0相同的 `common_ready`、历史行业映射和买入资格约束。T1/S0要求行业和个股双重状态。任一必要条件未知，Q保留unknown，不通过布尔短路伪装成确定0。
- RS沿用四段63有效观察、权重0.4/0.2/0.2/0.2。253点才可用，不阻止趋势资格。比较键采用与原版一致的NumPy 12位舍入；不把各行业内部归一化名次当成T0的全局RS。`rs_score`只接受已经核验的正值有效价格观察，不自行填行情。
- 休市可保留时点有效的状态事实；旧日RS不冒充本日观察。S0行业批缺RS整批按行业ID；某行业股票批缺RS只令该行业按证券ID；T0/T1全局批缺RS则全批按证券ID。缺RS不会被剔除或排到最末。
- 未承诺等待名单按当天竞争顺序重排。S0每个行业每轮选择一家公司，先全部行业第一轮，再第二轮。A/H重复线路被跳过时不消耗该行业本轮成功选择机会。
- 已承诺但尚未成交的买单保留预算和槽位，其执行优先级可以按当天排名重排；未获确认的推荐不占槽。部分成交优先完成，但取消/暂停和锁存退出优先于“补完初仓”。这就是设计中“尚未开始成交每日重排”与“已承诺占槽”的最小一致解释，不隐含撤掉旧委托抢新排名。
- 持仓、待买、锁存退出均按公司占槽，3行业/行业2公司/总6公司。同发行人两条线路只能选一条。调用方必须把已有占槽按本次已知生效分类更新；传入与本次解析身份相矛盾的占槽将报错，不能继续使用入场时分类。已存在迁移超限不强卖，禁止扩大超限或新增第4/第5行业；允许在既有行业中不扩大相关超限的补位。
- 行业转弱或资格失效取消未完成买入，但不触发旧持仓卖出；个股结构失效触发退出请求，已有锁存退出不会因恢复而取消。单纯排名下降不卖出。
- 未知暂停原候选，保留最后已知Q。`1→unknown→1`不创建新事件，`0→unknown→1`可创建资格上升；初始化以外第一次观测就是1且没有历史0时不凭空创建事件。账户起点的初始化必须显式 `bootstrap=True`，不可在有Memory时重放。
- 已确认占槽消费等待候选；占槽行后来消失本身不能创造重入。明确退出完成事件在unknown期间保留待重入，恢复已知Q=1时一次消费；重复event_id不会再次创建；同ID时间矛盾或晚周期后回放旧退出事件会报错。若完成时Q明确为0，则等待下一真实0→1。

同一时点部分成交订单之间没有方案规定的经济优先级，本适配器按稳定证券ID，整体仍先于未成交订单。需要改变时必须在执行适配协议中明确，不能按收益挑顺序。

## 与旧执行器集成所缺的工作

旧 `pv-strategy-20261020/code/execution.py::run` 使用静态证券集合、仅0/1状态、创建时固定排序和旧0.9/N预算，本模块没有直接改写或调用它。接入至少需要：

1. 按共同收盘截点连接历史名册、市值、南向买入/仅卖出、同源成员和冻结信号；输出明确的known/unknown及来源。保持三个版本共同数据范围；历史成员不齐不能以有数据者定义全市场。
2. 调用方持久化每次 `Decision.memories`，维护真实持仓/预约/退出锁存，将退出完成事件以稳定唯一ID投递；保留资格上升分项的前后证据。本模块的origin只区分资格上升、初始化、退出重入，市值/港股通/行业调整的细分归因由时点连接事件账提供，尚未伪造。
3. 对 `selected` 顺序依次验算0.90×NAV/6、剩余总投入、可用结算现金、费用与整手；首次真实准入同时冻结预算和股数上限，再形成 `Occupancy.pending_buy`。不得在仅有推荐时占用现金。若部分推荐因现金/手数被拒绝，必须将真实确认的预约反馈后在同截点补位，不能把推荐当成交。预算不自动日更，开盘和公司行为适配仍待实现。
4. 统一维护市场日历、真实可执行时点、涨跌停/T+1/停牌、原价成交、过去成交容量、南向人民币交收、汇率和权益；未知或错误不能由本模块输出“通过”来覆盖。每次执行之前还须按当时新获知事实重新核对资格。
5. 用真实历史前缀检查状态、时点映射、排名、候选、委托和现金。现有43项仅合成技术测试，尚无真实证券数据的S1轨迹或账户通过。

同一截点多次调用补位时应复用该截点首次输出的Memory并带上实际确认的预约；不得再次bootstrap。重复调用不能改写已经冻结的预算。
