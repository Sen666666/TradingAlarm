# 自动模拟仓 PAPER-OPEN-1

2026-10-27 用户明确要求新增100万元自动模拟仓，沿当前指引自行买卖，买卖均使用决策后下一交易日开盘价。已部署入口：http://127.0.0.1:8765/simulation ，首页导航“自动模拟仓”。产品版本 DESK-ACT20-2-PAPER；原产品合同保存在 `TradingAlarm/contracts/DESK-ACT20-1.json`。本轮是平台功能，不是新算法或历史研究回测。

## 账户与每日使用

- 一个独立的100万元模拟资金池，空仓开始。使用当前最新完整收盘2026-10-26作为首决策，补记2026-10-27开盘的四笔模拟买入；首次补记不是当时在线发生的真实成交。原真实账户不改。
- 页面展示当前现金、待收权益、持仓、含费成本、估值价格/日期、浮动损益、保护位、累计收益、回撤与净值曲线。
- “最近收盘决策”展示原指引以及对应的成交或跳过原因；“每日交易与持仓”按日期查看买卖明细及当日持仓；“每日账户记录”保存日末估值。可导出CSV。
- 最新完整收盘尚未发布时，已成交持仓使用当日开盘估值，并明确标注“开盘，待收盘”。不能将这份净值称为当日收盘收益。

## 策略与成交合同

复用 `desk.strategy.build_report` 的 ACT20_BREAK：原I-NR1入场、E0-NR1持有与退出、G1、RS-H1和S0容量不改。账户暂停/恢复依据模拟仓自己的净值，不继承真实账户或旧回测的状态。最多6股/3行业/每行业2股，首次15%净值和原90%投入约束；保留原指引股数上限，不自动加仓。

收盘决策保存后不可重写。只有下一交易日的未复权实际开盘价可以执行该决策；周末和休市按已核验日历跳过。买卖均零滑点，这是用户这次明确要求，与旧研究基础±5bps的成交假设不同，不能直接比较收益归因。

先处理卖出，再按原候选优先顺序买入。保留T+1、整手、现金、参考费用和开盘保护位约束。开盘价不高于保护位放弃买入；按实际开盘价在预算/现金/原股数上限内计算数量。卖出未完成后继续由后续收盘指引锁存退出。

模拟假设有效开盘即可以按开盘价成交，不证明涨跌停排队、实际流动性或券商成交。完整发布的交易日没有有效交易日线时不成交；尚未取得开盘数据则等待，不用别的日期或收盘价代替，不把查询失败当停牌。重启补处理仍使用原指定交易日开盘价。

费用沿冻结参考费表逐笔单列，不宣称是用户券商实收。普通权益按源条款处理；未知分红到账日保留待收现金，不投入可用资金；未知新增股份上市日暂不可卖。配股沿不认购研究约定，不虚构出资或获配。

## 自动运行与持久化

服务运行时，每30秒检查任务，模拟同步至多每5分钟自动尝试一次；交易日9:35起查询开盘，使用既有授权同花顺9602日线/权益读取。只查询当前模拟持仓和待执行股票，最多12只。原15:30收盘更新发布后立即触发模拟续算。手动“立即同步”可即时检查。关机、睡眠或会话过期不能取得新资料，恢复服务/登录后继续。

`TRADINGALARM_ENABLE_LIVE=1` 是既有在线**行情读取**开关，不是实盘下单开关：行情200/207/210、模拟读取210/211。本应用没有券商委托接口。模拟买卖只提交本地SQLite事务。

真实账本：`TradingAlarm/runtime/account.sqlite3`。模拟账本：`TradingAlarm/runtime/simulation.sqlite3`，两者独立。模拟库保存不可变成交事件、每次收盘指引、逐日快照、开盘来源和执行回执。原始行情响应留存在 `TradingAlarm/runtime/paper-quotes/`。

一批开盘事件及执行回执在同一 SQLite IMMEDIATE 事务提交，决策日和成交事件ID唯一。界面读取使用单一数据库读事务，避免同步瞬间把旧现金与新成交混合显示。WAL持久化，不依赖页面内存或浏览器存储；关页面不清空，重启不重复成交。不要删除runtime目录；机器迁移/备份应包含账本和原始响应。
